## Your Implementation Context

### What You're Building
AvocadoDB is a span-based context compiler that replaces traditional vector databases' chaotic "top-k" retrieval with deterministic, citation-backed context generation. 

### Why This Matters
Current RAG systems are fundamentally broken:
- Same query → different results each time
- Token budgets wasted on duplicates
- No citations or verifiability
- Hallucinations from inconsistent context

AvocadoDB fixes this with deterministic compilation, perfect citations, and 95%+ token utilization.

## Implementation Rules

### 1. Determinism is Sacred
- **Every** operation must be reproducible
- Use stable sorts with tie-breakers: `(score, artifact_id, start_line)`
- No randomness, no undefined iteration order
- Test determinism obsessively

### 2. Simplicity First
- Brute force vector search is fine (we're not at scale yet)
- Greedy token packing is sufficient
- Basic keyword matching for lexical search
- No fancy UI - functionality over form

### 3. Code Standards
```rust
// Every public function needs:
/// Documentation comment explaining purpose
/// 
/// # Arguments
/// * `query` - The search query
/// 
/// # Returns
/// * `Result<WorkingSet>` - Compiled context or error
pub fn compile(query: &str) -> Result<WorkingSet> {
    // Implementation
}
```

### 4. Testing Requirements
- Every algorithm needs a determinism test
- Every API endpoint needs an integration test
- Document test commands in README

### 5. Coordination Protocol
- Check dependencies before starting work
- Push to feature branches, not main
- Add status updates as comments in your code
- Flag blockers immediately
